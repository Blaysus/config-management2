# Практическая работа № 2. Вариант 22. Этап 1

Минимальный прототип инструмента визуализации зависимостей пакетов
Alpine Linux (apk). Программа читает пять настроек из TOML-файла,
проверяет их и выводит в формате `ключ = значение`.

Выполнен только этап 1: загрузка настроек, проверка параметров,
понятные сообщения об ошибках и демонстрационные примеры.
Получение зависимостей, обход графа и PlantUML относятся к следующим
этапам и пока не реализованы. Сетевых запросов на первом этапе нет.

## Требования и запуск

Нужен **Python 3.11 или новее**: модуль `tomllib` входит в его стандартную
библиотеку. Сторонние пакеты, установка через pip и сборка не требуются.

Откройте терминал в каталоге `prac2` и выполните:

```sh
python3 -m src.main
```

Выбор другого TOML-файла:

```sh
python3 -m src.main --config examples/test_config.toml
```

Скрипт для macOS и Linux:

```sh
./run.sh --config examples/config.toml
```

При необходимости его можно запустить как `sh run.sh`. Для выбора
интерпретатора: `PYTHON=python3.11 ./run.sh`.
В Windows используйте `py -3 -m src.main` из каталога проекта.

Справка:

```sh
python3 -m src.main --help
```

Опция `--config PATH` выбирает файл; по умолчанию используется
`examples/config.toml` из каталога проекта. Все пять настроек программы
задаются только в TOML, отдельных опций для них нет.
Относительный путь в `--config` отсчитывается от текущего каталога
терминала. Скрипт `run.sh` также работает при запуске из другого каталога.

## Настройки

Все пять ключей обязательны и размещаются на верхнем уровне TOML,
без секций. Неизвестные ключи считаются ошибкой, чтобы выявлять опечатки.

| Ключ | Тип TOML | Назначение и проверка |
| --- | --- | --- |
| `package_name` | строка | Имя пакета: первая буква латинская или цифра, далее также допустимы `.`, `_`, `+`, `-`. Имена тестовых узлов `A`, `B`, `C` разрешены. |
| `repository` | строка | При `test_mode = false` нужен HTTP(S)-URL с узлом и корректным портом, без пробельных или управляющих символов. При `true` нужен существующий читаемый обычный файл. |
| `test_mode` | логическое | Только `true` или `false` без кавычек. Строки и числа не принимаются. |
| `package_version` | строка | Непустая строка, начинающаяся с цифры; далее допустимы латинские буквы, цифры, `.`, `_`, `+`, `~`, `-`. Например, `"1.3.1-r1"`. |
| `max_depth` | целое число | Глубина не меньше `0`. Ноль задает анализ только исходного пакета для будущего обхода графа. Дроби, строки и логические значения не принимаются. |

Версия проверяется по базовому текстовому формату. Наличие пакета,
версии и доступность удаленного репозитория на этапе 1 не проверяются.
Адрес и версия в примере служат для демонстрации настроек.

Относительный путь тестового репозитория отсчитывается **от каталога
TOML-файла**. Абсолютные пути и `~` также поддерживаются. При выводе
сохраняется исходное значение пути из конфигурации.
Файл пока проверяется только на доступность, его содержимое не разбирается.

## Примеры

`examples/config.toml`:

```toml
package_name = "zlib"
repository = "https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64"
test_mode = false
package_version = "1.3.1-r1"
max_depth = 3
```

Результат `python3 -m src.main`:

```text
package_name = zlib
repository = https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
test_mode = false
package_version = 1.3.1-r1
max_depth = 3
```

Пример тестового режима `examples/test_config.toml`:

```toml
package_name = "A"
repository = "test_repository.txt"
test_mode = true
package_version = "1.0-r0"
max_depth = 0
```

Результат `python3 -m src.main --config examples/test_config.toml`:

```text
package_name = A
repository = test_repository.txt
test_mode = true
package_version = 1.0-r0
max_depth = 0
```

В `examples/test_repository.txt` записан небольшой граф в условном
формате `пакет: зависимости`. На этом этапе достаточно существования
файла; формат его чтения будет реализован на этапе работы с графом.

## Демонстрация ошибок

Для каждого параметра подготовлен отдельный TOML-файл с ошибкой.
Запустите по очереди:

```sh
python3 -m src.main --config examples/errors/package_name.toml
python3 -m src.main --config examples/errors/repository.toml
python3 -m src.main --config examples/errors/test_mode.toml
python3 -m src.main --config examples/errors/package_version.toml
python3 -m src.main --config examples/errors/max_depth.toml
```

| Файл | Ошибка | Что будет в сообщении |
| --- | --- | --- |
| `package_name.toml` | Пробел в имени | `package_name: начните с латинской буквы или цифры` |
| `repository.toml` | Использован FTP | `repository: ожидается URL с http:// или https://` |
| `test_mode.toml` | `"false"` вместо `false` | `test_mode: ожидается true или false без кавычек` |
| `package_version.toml` | Пустая версия | `package_version: ожидается непустая строка` |
| `max_depth.toml` | Отрицательная глубина | `max_depth: ожидается целое число не меньше 0` |

Пример сообщения:

```text
Ошибка: max_depth: ожидается целое число не меньше 0
```

Ошибки направляются в `stderr`, настройки при ошибке не выводятся.
Программа завершается с кодом `2`; успешный запуск имеет код `0`.
Сообщается первая найденная ошибка. Также обрабатываются отсутствие
конфигурации, неверный UTF-8, некорректный TOML, дублирование ключей,
пропущенные и неизвестные настройки, отсутствие или недоступность
тестового файла, неправильный порт URL и ошибки аргументов командной строки.

## Проверка

Из каталога проекта:

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют допустимые настройки, ошибки всех пяти параметров,
граничную глубину `0`, оба режима источника, относительные и абсолютные
пути, ошибки чтения TOML, вывод CLI и запуск скрипта из другого каталога.
Сеть и сторонние пакеты для тестов не нужны.

## Структура и функции

```text
prac2/
├── src/
│   ├── __init__.py
│   ├── config.py
│   └── main.py
├── tests/
│   ├── test_config.py
│   └── test_cli.py
├── examples/
│   ├── config.toml
│   ├── test_config.toml
│   ├── test_repository.txt
│   └── errors/                 # Ошибка для каждого из пяти параметров
├── .gitignore
├── run.sh
└── README.md
```

Основной код находится в обычных `.py`-файлах.

| Элемент | Назначение |
| --- | --- |
| `Config` | Неизменяемый объект с пятью проверенными настройками. |
| `ConfigError` | Общая ошибка чтения и проверки конфигурации. |
| `load_config(path)` | Читает TOML, обрабатывает ошибки файла и вызывает проверку. |
| `parse_config(data, base_dir)` | Проверяет ключи, тип режима и значения, создает `Config`. |
| `_validate_fields(data)` | Проверяет наличие обязательных ключей и отсутствие лишних. |
| `_require_text(value, name)` | Проверяет строковый тип, непустое значение и управляющие символы. |
| `_validate_package_name(value)` | Проверяет имя пакета. |
| `_validate_package_version(value)` | Проверяет базовый текстовый формат версии. |
| `_validate_repository(value, test_mode, base_dir)` | Выбирает проверку URL или файла. |
| `_validate_url(value)` | Проверяет HTTP(S)-адрес без обращения к сети. |
| `_validate_test_file(value, base_dir)` | Проверяет существование и доступность локального файла. |
| `_validate_max_depth(value)` | Проверяет целую неотрицательную глубину. |
| `create_parser()` | Формирует справку и опцию `--config`. |
| `print_config(config)` | Выводит пять строк в формате `ключ = значение`. |
| `main(argv=None)` | Запускает приложение и возвращает код завершения. |

## Соответствие требованиям оформления

Проверены правила со страниц 4–7 задания. Проверка кода охватывает
как `src`, так и `tests`.

| Правила | Результат проверки |
| --- | --- |
| С1–С5: структура | Есть `README.md`, `.gitignore`, `src`, `tests` и `run.sh`. |
| Г1–Г5: лишние файлы | Файлы проекта текстовые; кэш Python, архивы, результаты сборки и настройки редакторов исключены через `.gitignore`. |
| Р1: размер файла | Каждый файл короче 1000 строк. |
| Р2: длина строк Python | Максимум 80 символов при допустимых 80. |
| Р6: длина строк остального кода | Строки `run.sh` короче 120 символов. |
| Ф1: длина функций | Максимум 17 строк при допустимых 40, включая docstring. |
| А1: аргументы | Максимум 3 аргумента при допустимых 7, включая `self`. |
| К1: документация | Все модули, классы и функции Python имеют docstring. |
| Ц1: сложность | Максимальная цикломатическая сложность по AST — 6 при допустимых 10. |
| М1: числа в сравнениях | В числовых сравнениях применяются именованные константы. |
| И1: имена Python | Используются соглашения PEP 8; `setUp` переопределяет стандартный метод `unittest.TestCase`. |

Ограничения для других языков к этому проекту не применяются.
30 автоматических тестов проходят без обращения к сети.

С6 относится к истории коммитов и проверяется при публикации.
Для отдельного репозитория содержимое `prac2` нужно разместить в его
корне. Если использовать общий репозиторий с другими работами,
требования к корневым файлам, составу файлов и истории относятся ко
всему репозиторию. `.gitignore` не удаляет уже отслеживаемые файлы.
